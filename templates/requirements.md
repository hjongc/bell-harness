# Requirements

Use the `probe` requirements interview to capture requirements from the project's planning documents and get the user's approval for each row. Give each requirement a stable ID and observable acceptance criteria. Link its implementation spec when available. Review the table in short interviews at milestones and after unattended runs.

- `todo`: approved and ready to plan.
- `in-progress`: implementation has started.
- `done`: the acceptance criteria have passed and the item is complete.
- `dropped`: the user decided to drop it.
