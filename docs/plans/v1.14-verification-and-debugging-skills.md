# v1.14-verification-and-debugging-skills: share two focused workflows

Status: implemented

## Context

The user requested that the shared harness include the offline verification checklist and systematic debugging workflow discussed after the v1.13 pilot. The pilot showed comparable results on one task. The additional workflow is useful as a selectable option for the situations it names. GitHub Actions diagnosis stays outside the shared set.

## Decisions

- D1: Ship offline-verification and systematic-debugging alongside the existing eight shared skills -- why: the user approved applying both workflows to this harness and excluded the GitHub Actions skill -- by: user -- paths: skills tests/test_skills.py -- supersedes: v1.5-audit-fixes#D3
- D2: Cover artifact or normal-entry-point verification and recurring or unclear failures with separate, narrow descriptions -- why: the existing spec, preflight and eval skills cover planning, push checks and comparative evaluations -- by: observed -- paths: skills tests/test_evals.py

## Scope

- Add `skills/offline-verification/SKILL.md` for executing the normal or installed entry point with allowed offline inputs, checking the relevant effect and reporting exact evidence and gaps.
- Add `skills/systematic-debugging/SKILL.md` for reproducing intermittent, unclear or recurring failures, isolating the first incorrect state and validating a minimal fix. Write original instructions for the harness.
- Add two English and two Korean routing cases under `evals/cases/`. Reuse existing small-edit, eval and preflight cases as negative controls. Update `tests/test_skills.py` and `tests/test_evals.py` for the new inventory and cases. Update `README.md`, `SOURCES.md`, `AGENTS.md` and the roadmap.
- No GitHub Actions skill, vendor files, dependencies, global instructions, global installation, live model evaluation or changes to setup and doctor.

## Acceptance tests

1. The two skill files pass the existing frontmatter and format checks. A temporary-home installation and doctor discovery see the exact ten skills. No GitHub Actions skill is present.
2. Stub-based eval tests accept both skills with verified events for their four routing cases and reject a mismatched skill. Existing unrelated routing cases still pass.
3. Independently exercise both instructions on isolated offline examples. Check that verification runs the packaged entry point and reports gaps, and that debugging demonstrates the failing behavior and the fix without exceeding scope.
4. `scripts/check` exits 0 and prints `GUARD: real home unchanged`.

## Done criteria

Acceptance checks 1–4 pass. Only the listed files change. Record the offline evidence and the status of live evaluation.
