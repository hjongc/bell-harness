# v1.18-check-fixture-performance: measure the remaining offline check bottleneck

Status: implemented

## Context

v1.8 parallelized the check. v1.12 removed unnecessary installations and left repeated fixture preparation as a candidate. A three-sample temporary-home probe measured fixture construction at roughly 0.36–0.46 seconds per instance, alongside setup at 1.57–1.80 seconds. A separate identical-tree microprobe measured a 0.331-second median for copy and commit and 0.168 seconds for an independent local clone. The full-run gain remains unmeasured.

## Decisions

- D1: Profile the check before changing fixture lifetime -- why: module timings overlap under the current worker pool, so a local speedup may not reduce the full run -- by: observed -- paths: scripts/check tests/test_setup.py tests/test_doctor.py
- D2: Reuse the previous ten percent median target when deciding whether to keep the prototype -- why: v1.12 established a measurable threshold for a similarly scoped test optimization -- by: observed -- paths: docs/plans/v1.12-doctor-check-speed.md
- D3: Profile the offline check and use the documented gate for a prototype -- why: the user approved v1.16 through v1.18 on 2026-11-22 with the reply “승인” -- by: user

## Scope

1. Take two `scripts/check --jobs 4` baseline profiles on the same checkout without competing check runs. Record full wall time, suite start and finish times by worker, and temporary measurements for fixture construction in the check's longest suites. Record one serial run for attribution.
2. Prototype once only if repeated fixture creation on the consistently slowest worker takes at least twenty percent of full wall time in both profiles. The microprobe removed about half the preparation time, so a smaller share makes the ten percent full-run target unlikely. Reuse one committed template per process and copy it into independent temporary worktrees. Keep each test's own home, Git configuration, index, hooks and writable files. Seed the template from the same current working-tree bytes as the existing fixture, including modified and nonignored untracked inputs. Preserve existing subprocess and integration coverage.
3. If the profiles place the bottleneck elsewhere, record it for a separate proposal and finish this item with the profile. If one suite repeatedly runs alone at the end, report the idle-worker interval and identify possible groups that preserve unittest fixture scope. The runner, setup and doctor command behavior, CI, default worker count and home guard stay outside the implementation scope.

## Acceptance tests

1. For a prototype, compare three alternating baseline and candidate pairs on one machine and checkout, at four workers, with identical test IDs. Run the candidate once serially. Report raw samples, medians and the slowest modules.
2. Keep the change only if median full wall time improves at least ten percent, tests retain equivalent inputs and verdicts, and all runs print `GUARD: real home unchanged`. Exercise a modified working-tree file and confirm changes stay local to each fixture.
3. A profile-only or below-target outcome records the measurements and the decision to keep the existing fixture. Run the final `scripts/check` once on the delivered state.
