# v1.17-instruction-status: show uncommitted project instructions

Status: implemented

## Context

A project can pass doctor while its instruction files exist only in the current checkout. In a temporary Git project, doctor accepted an untracked root `CLAUDE.md` and gave no indication that `src/AGENTS.md` was also untracked. Show which instructions are absent from or differ from the current commit before reviewing a branch or switching tools.

## Decisions

- D1: Add an opt-in project-only view based on Git status -- why: instruction format and inclusion in the current commit answer different questions, and a temporary repository reproduced the gap -- by: observed -- paths: bin/doctor tests/test_doctor.py
- D2: Add the opt-in instruction status within the approved offline sequence -- why: the user approved v1.16 through v1.18 on 2026-11-22 with the reply “승인” -- by: user

## Scope and interface

```sh
bin/doctor --project-only <checkout-root> --instruction-status
```

- Reuse the existing project checks and report formatter. Add status for root and nested `AGENTS.md` and `CLAUDE.md` files in the current Git worktree. Require a checkout root for the status view. Unsupported flag combinations return the existing argparse usage code 2.
- Use a filtered `git --no-optional-locks -C <path> -c core.fsmonitor=false status --porcelain=v1 -z --untracked-files=all --no-renames --ignore-submodules=all` call with top-anchored glob pathspecs for both names. Disable the configured fsmonitor hook only for this query. Treat untracked, staged and unstaged states independently. Preserve Git's ignore behavior and omit unrelated paths.
- Emit one `WARN untracked instruction: <quoted-relative-path>` for untracked files and `WARN uncommitted instruction: <quoted-relative-path> (index=<X>, worktree=<Y>)` for each changed tracked path. Use `.` for a blank status column and sort paths by their decoded string. An unmerged status retains Git's original columns. A clean query emits `PASS instruction status: no uncommitted instructions`.
- A failed query or a path outside a checkout root emits `WARN instruction status` with a short reason. The project checks retain their exit semantics. The default invocation, merge policy and permission boundaries retain their existing contracts.

## Acceptance tests

1. A single temporary checkout reports an untracked nested file, a staged addition, a file with both staged and unstaged changes, and a tracked deletion. Names with spaces are unambiguous. An ignored and an unrelated file produce no status lines.
2. After committing the relevant files, the view reports clean. A separate unborn branch still reports a staged addition. A non-root path and a failed status query report unavailable. An unsupported flag combination exits 2.
3. The query preserves the worktree and index and does not run the configured fsmonitor hook. The normal project-only invocation retains its output and exit behavior. `scripts/check` passes and prints `GUARD: real home unchanged`.

## Done condition

Acceptance checks 1–3 pass and the diff is confined to the named files.
