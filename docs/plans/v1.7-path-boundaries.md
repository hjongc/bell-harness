# v1.7-path-boundaries: audit filesystem boundaries

Status: implemented

## Context

Continue the harness audit with temporary-home and temporary-repository reproducers. A retirement path can move or restore an item through a symlinked parent. The privacy scan follows a stale tracked path outside its work tree and can crash on an allow-file comment. The home guard misses edits to existing backup manifests. Equivalent retirement path spellings can cause a valid item to disappear from the plan.

## Decisions

- D1: Require a real backup directory path, check the ancestors of retirement paths, and check both sides of a retirement restore before undoing that backup -- why: a symlinked parent can redirect a move while a leaf symlink is itself a supported retirement item -- by: observed -- paths: bin/setup bin/doctor lib/harness.py tests/test_setup.py
- D2: Scan Git working tree paths only when their ancestors inside the scan root are real directories -- why: Git can list a tracked descendant beneath a replacement symlink and the scanner would read its target file -- by: observed -- paths: lib/privacy.py tests/test_privacy.py
- D3: Ignore blank lines and comments when parsing the privacy allow file and report incomplete rules by line -- why: a one-token comment can crash the scanner while processing a finding -- by: observed -- paths: lib/privacy.py tests/test_privacy.py
- D4: Include regular backup manifests in the home guard snapshot and record symlinks by their link text -- why: an in-place change to a manifest leaves the directory listing unchanged -- by: observed -- paths: scripts/check tests/test_check.py
- D5: Normalize each retirement path before deduplicating and checking containment -- why: two spellings of the same item can otherwise exclude each other as ancestors -- by: observed -- paths: lib/harness.py tests/test_setup.py

## Scope

- `bin/setup`, `bin/doctor`, `lib/harness.py`, `tests/test_setup.py`: enforce and test the retirement boundary.
- `lib/privacy.py`, `tests/test_privacy.py`: check Git path ancestors and parse allow rules before scanning.
- `scripts/check`, `tests/test_check.py`: snapshot manifest contents for active and restored backups.
- `README.md`, `AGENTS.md`, this spec and the roadmap: record the behavior and results.
- No setup on the real home, live model calls, global changes, or changes in another repository. Keep the existing settings-file symlink behavior. Handle static symlink layouts and paths changed between install and restore.

## Acceptance tests

1. Install and dry-run report a retirement path under a symlinked parent and preserve the external file. A sibling leaf symlink can still be moved and restored. A blocked restore of a retired path keeps its backup and makes no changes from that backup. Setup and restore return 2 before mutating anything when the backup directory path has a symlink.
2. Privacy finds the target string of a leaf symlink while ignoring tracked descendants beneath that symlink.
3. Full-line allow-file comments are ignored. An incomplete allow rule is reported by its line without printing the rule text, and findings are still reported.
4. Guard snapshots change after edits to existing active or restored manifests. A symlinked manifest's target content is excluded.
5. An equivalent default and local retirement path is planned once and saved in the backup.

## Done criteria

The focused tests reproduce the prior failures and pass with the fixes. `scripts/check` exits 0 and prints `GUARD: real home unchanged`. The changes stay within this spec.

## Starting behavior

1. Dry-run listed the outside retirement path. A restore through a replacement parent announced that it would undo the backup.
2. The privacy scan reported both the actual symlink and the outside file under the stale tracked path.
3. An allow-file comment made the scan return 1 with a traceback. An incomplete rule produced no usable diagnosis.
4. Editing either an active or restored manifest left the backup snapshot unchanged.
5. The same retirement path with and without a dot component appeared zero times in dry-run output.
