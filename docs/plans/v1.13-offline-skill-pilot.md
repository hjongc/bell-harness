# v1.13-offline-skill-pilot: trial a project verification skill

Status: implemented

## Context

The v1.9 comparison used synthetic tasks. A short offline checklist was more consistent about separating observed evidence from unrun checks. This supports a one-task trial before making a shared skill available in all sessions.

## Decisions

- D1: Base the pilot on the recorded v1.9 trial and assess results at a project entry point -- why: the synthetic comparison measured proposed work and did not measure execution on a real change -- by: observed -- paths: docs/plans/v1.9-project-doctor.md
- D2: Run one offline pilot on an approved public harness task in temporary checkouts -- why: the user approved all four recommended roadmap options -- by: user

## Scope

- Pick one already approved command-line change with a repeatable offline check. The recommended project is the public harness. Freeze the approved task's pre-change tree so a later pilot can replay it after implementation. Use separate temporary checkouts, the same base tree, user task and allowed actions, and compare the existing spec and preflight workflow against the same workflow with an explicitly supplied verification checklist.
- Candidate covers spec boundaries, fake or synthetic inputs, the actual installed or normal entry point, recorded command and exit code, and remaining unverified work. Record the plan, commands, results, and scope deviations in the trial report. No full project history or personal data is needed.
- A temporary skill may follow Agent Skills format. No global installation, new shared skill, paid live call, outside project change or external action is part of this trial. If two comparable runs are unavailable, record that the comparison is incomplete.

The public skill format uses a concise description and supporting files. Use a shared format if testing an explicitly selected trial skill. [Agent Skills specification](https://agentskills.io/specification) · [Codex skills](https://learn.chatgpt.com/docs/build-skills) · [Claude Code skills](https://code.claude.com/docs/en/skills)

## Acceptance tests

1. Record a checklist before each condition: scope adherence, observable command evidence, invocation at the normal entry point, named verification gaps and respect for external action permissions.
2. Keep the candidate only if it recovers at least one missed verification item and preserves correctness and permissions. Record the effort or time difference when comparable. Otherwise, retain the existing workflow.
3. Report one trial as one trial. No routing, success-rate or cross-project performance claim follows from a single example.

## Trial and result

Use the approved backup-inventory CLI task. The pre-change snapshot is `14b3bfc` and the completed change is `35495a3`. Two separate archive checkouts used the same task, same implementation tree and same permissions. The control used spec and preflight guidance. The candidate received the additional offline checklist. Each used a synthetic home and Git configuration with real `bin/setup` entry-point calls.

| Criterion decided before the trial | Control | Candidate |
|---|---|---|
| Identify approved scope and avoid real-home operations | Met | Met |
| Exercise normal and linked inputs through the CLI | Met | Met |
| Record commands, exit codes and results | Met | Met |
| Compare state across the read-only or rejected boundary | Met | Met |
| Name what remains unverified | Met | Met |

Both sessions observed exit 0 for valid inventory, exit 1 for an inventory with unsafe or damaged records, and exit 2 for rejected backup inputs. Both preserved snapshots around read-only or rejected operations and kept legitimate restored entries usable. The candidate added a direct pre-change comparison for a linked earlier-root record and checked numeric restore order end to end. The control already met all five criteria. Keep the existing workflow and leave the extra checklist optional. This one trial does not establish a timing or general success-rate difference.

The archive snapshots had no Git history and the pilot did not rerun the complete suite. On the real working tree, the independent `scripts/check` run passed 102 tests in 58.546 seconds and printed `GUARD: real home unchanged`.
