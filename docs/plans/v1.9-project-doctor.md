# v1.9-project-doctor: read-only project diagnostics

Status: implemented

## Context

Project diagnosis ran the harness commit hook against historical messages. That could invoke the inspected project's own hook and repeated Git calls for every commit. Diagnose the project without running hooks, and provide an option that omits machine checks.

## Decisions

- D1: Use the same commit message rules from the Git hook and from diagnosis, with hook chaining limited to real Git hook invocations -- why: offline diagnosis created a marker through the inspected repository's hook -- by: observed -- paths: bin/doctor git/hooks/commit-msg lib/commit_message.py
- D2: Add `bin/doctor --project-only PATH` for project checks without machine checks or live discovery -- why: project diagnostics should work in an uninstalled checkout or CI -- by: observed -- paths: bin/doctor tests/test_doctor.py

## Scope

- `bin/doctor`, `git/hooks/commit-msg`, `lib/commit_message.py`, `tests/test_doctor.py`: shared validation, batched history, project-only mode and regression coverage.
- `README.md`, `AGENTS.md`, this spec and the roadmap: document the behavior and evidence.
- Keep actual Git hook chaining and the committed-config policy. Keep the upstream range or the last 20 commits when no upstream exists. Run only local and temporary checks. Compare skill guidance on fixed synthetic cases. No skill installation or paid live evaluations.

## Acceptance tests

1. Both project modes report bad commit messages without executing a marker-writing project hook. Project-only succeeds when a machine install check would fail.
2. The existing commit hook tests pass. The previous and current history checks agree on commit verdicts in the same 20-commit temporary repository without a project hook. Record subprocess counts and median wall times.
3. `scripts/check` passes with `GUARD: real home unchanged`.

## Skill trial criteria

Score each answer for explicit evidence versus unverified work, respecting the stated scope and external-action boundary, and a concrete check at the normal entry point. For the timeout case, also require both event orders and a no-duplicate invariant. For the package case, require an installed-artifact test independent of the source tree. Grade the same prompts with and without the candidate guidance.

## Offline skill trial

Two rounds used three synthetic tasks per condition. The tasks covered an ambiguous timeout, installed-CLI asset verification and CI diagnosis. One agent per condition received the same cases with no extra guidance, the reviewed systematic-debugging procedure, or a short project offline-verification procedure. Agents proposed checks without executing case actions. The second round used the rubric above.

- The control and the offline procedure both proposed testing both timeout orders and preventing duplicate posts. Systematic-debugging made the uncertainty in the late-confirmation policy explicit and left the duplicate invariant unstated.
- All three conditions proposed invoking the installed CLI outside the source tree. The offline procedure consistently separated supplied evidence from commands and outcomes it had not verified.
- The bundled OpenAI `gh-fix-ci` script passed an isolated fake-`gh` test for a Linux Actions DNS failure, a pending log and a Buildkite URL. It misclassified an external-provider URL containing `/runs/<id>`. No live PR, authentication or installation was used.
- Start with the project offline-verification procedure when a task calls for it. The trial is a small comparison of proposed work, with no claim of improved real task pass rates.

## Verification

In the starting implementation, the focused test found the marker written by the inspected repository's hook. Both diagnostic modes now pass the marker test. A second fixture verifies that Git history uses the committed UTF-16 policy even when the working-tree policy differs.

The 20-commit benchmark called only the commit history check, used no upstream and had no project-local hook. In three alternating trials per implementation, both versions rejected the same three commits. The median went from 3.538 seconds to 0.087 seconds. Direct diagnostic subprocess calls went from 43 to 5, excluding subprocesses launched inside the old hook.

Final `scripts/check` passed 95 tests in 64.091 seconds with four workers and printed `GUARD: real home unchanged`. The project-only check passed on this repository.
