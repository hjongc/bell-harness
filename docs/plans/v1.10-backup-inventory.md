# v1.10-backup-inventory: inspect backup records before restoring

Status: implemented

## Context

Setup can restore a named backup or all active backups. The operator currently has to find IDs and assess their records manually. In a temporary home, both earlier-root discovery and restore dry-run read an outside manifest through a linked backup ID or a linked manifest. A manifest with invalid UTF-8 caused a traceback.

## Decisions

- D1: Reuse the existing backup names, order and manifest checks -- why: the inventory must describe the backups the current restore command understands, including restored entries -- by: observed -- paths: bin/setup lib/harness.py
- D2: Keep restored genuine manifests and their valid rows available to earlier-root discovery -- why: v1.5-audit-fixes#D5 records that earlier install roots are needed for repairing moved checkouts, including when some rows are damaged -- by: observed -- paths: lib/harness.py tests/test_doctor.py
- D3: Approve backup inventory with shared read-side path checks -- why: the user approved all four recommended roadmap options -- by: user

## Scope

- Add `bin/setup --list-backups` and document it. Print newest first by the timestamp and numeric suffix. Emit backup ID, `active` or `restored`, and manifest health `valid`, `damaged`, or `unsafe` per recognized entry. An empty directory is a successful empty inventory. Manifest health describes the record and does not predict the result of a restore.
- Recommended scope also shares rejection of stable symlinks at the backup root, ID directory and manifest between listing, restore and earlier-root discovery. For earlier-root discovery, keep valid rows in a regular manifest when other rows are malformed.
- Production files proposed are `bin/setup`, `lib/harness.py`, and `README.md`. Reuse `tests/test_setup.py` and `tests/test_doctor.py`. Keep the current record format, settings symlink support, restoration order and backups on disk. Concurrent layout changes and backup deletion are outside the proposal.
- Exit 0 for empty or all-valid inventory, 1 after listing entries with invalid or unsafe records, and 2 for invalid arguments or an unsafe backup root. Treat listing as an exclusive operation.

## Acceptance tests

1. List active and restored backups in a temporary home. Numeric suffix `-10` sorts before `-2` in newest-first output. Inventory shows no action values or raw manifest lines.
2. Use a sentinel outside file. With links at the backup ID or manifest, inventory reports an unsafe entry. Under the recommended scope, restore rejects it before undoing that backup and earlier-root discovery does not load it.
3. A regular manifest with invalid UTF-8 or malformed rows produces a bounded diagnostic with no traceback. Verify earlier-root discovery still finds a valid row in a genuine partly damaged manifest.
4. Assert identical before and after snapshots for inventory, existing restore tests pass, and `scripts/check` reports `GUARD: real home unchanged`.

## Verification

Focused inventory, restore and moved-root checks passed. The final `scripts/check` passed 99 tests in 83.211 seconds with four workers and reported `GUARD: real home unchanged`.
