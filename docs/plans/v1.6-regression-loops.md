# v1.6-regression-loops: harness regression audit

Status: implemented

## Context

The audit request calls for at least five rounds of reproducing a problem, fixing it and checking the result. Six rounds cover restore, installation checks, Markdown parsing, eval isolation, eval grading and staged diff diagnostics.

## Decisions

- D1: Validate the fields consumed by undo before applying any entry in the selected backup -- why: valid JSON with an incomplete link or settings record bypasses the existing damage check and can leave a partial restore -- by: observed -- paths: bin/setup tests/test_setup.py
- D2: Doctor uses the same previous-root set as setup when classifying stale links -- why: after repair, doctor can pass a stale link that setup would remove -- by: observed -- paths: bin/doctor lib/harness.py tests/test_doctor.py
- D3: Apply the same fenced-code boundaries to decision records and table citations -- why: an example can be appended to a wrapped record or mistaken for a real citation -- by: observed -- paths: lib/decisions.py tests/test_decisions.py
- D4: Remove inherited Git repository-local variables from fixture and host commands -- why: invoking the evaluator from a Git context can redirect fixture staging and commits to another repository -- by: observed -- paths: evals/run.py tests/test_evals.py
- D5: Count a Codex skill command after successful completion and require a nonempty final answer -- why: an interrupted command or silent host can yield a passing grade -- by: observed -- paths: evals/run.py tests/test_evals.py
- D6: Pin staged patch inter-hunk context to zero -- why: a Git config that merges hunks can shift reported line numbers when blank context prefixes are suppressed -- by: observed -- paths: git/hooks/pre-commit tests/test_hooks.py

## Scope / Non-goals

- In: the files listed below, Python 3.9 standard library and existing Git commands.
- Out: real-home setup or restore, paid live evals, changes to global configuration, publication, and broader parser or policy changes.

## Changes by file

1. `bin/setup`, `tests/test_setup.py`: validate malformed manifest payloads before undoing the affected backup.
2. `bin/doctor`, `lib/harness.py`, `tests/test_doctor.py`: flag previous-root stale links and reserve the unmanaged warning for foreign entries.
3. `lib/decisions.py`, `tests/test_decisions.py`: share fence handling and stop record continuation at fences.
4. `evals/run.py`, `tests/test_evals.py`: isolate fixture Git context and check command completion and final output.
5. `git/hooks/pre-commit`, `tests/test_hooks.py`: force zero inter-hunk context and assert the staged line number.
6. `README.md`, `AGENTS.md`: document backup validation, earlier roots and the eval checks.
7. This spec and `docs/plans/roadmap.md`: record reproducers and status.

## Acceptance tests

1. An incomplete link or settings record leaves that backup, settings and Git hooks path unchanged and returns 2.
2. Doctor fails for a stale link in an earlier root that setup would remove.
3. A fenced block after a decision does not change its fields, and a fenced table example does not produce a real citation.
4. Inherited Git overrides leave the caller repository's HEAD and staged content untouched, and the eval host uses its own fixture repository and index.
5. A started or failed Codex read, a backup filename, and an empty host answer each fail the relevant eval.
6. The hook reports the staged line number even when Git merges hunks and suppresses blank context prefixes by default.

## Done criteria

Each acceptance test fails against the starting implementation and passes after the corresponding fix. `scripts/check` exits 0 with the real-home guard intact. Only the files in Changes by file change.

## Reproduction

The acceptance tests are in `tests/test_setup.py`, `tests/test_doctor.py`, `tests/test_decisions.py`, `tests/test_evals.py` and `tests/test_hooks.py`. Each uses fixed input in a temporary home, repository or subprocess stub.

| Round | Starting behavior observed on the same input |
|---|---|
| 1 | Restore exited 1 with `KeyError: 'target'` or `KeyError: 'key'`. The missing target case undid settings and Git config first. |
| 2 | Setup planned to unlink the stale skill while doctor exited 0. |
| 3 | The record reported a bad author, and the citation check reported a reference inside the fenced example. |
| 4 | The temporary caller repository's HEAD changed during fixture preparation. |
| 5 | Started and failed Codex commands, a backup filename and an empty final answer all received passing grades. |
| 6 | The hook reported line 3 for a staged match on line 4. |
