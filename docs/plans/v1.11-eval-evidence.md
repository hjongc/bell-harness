# v1.11-eval-evidence: verify skill usage from tool results

Status: approved

## Context

The evaluator accepted two synthetic events as successful uses of `probe`: a completed Codex command that only printed the skill path, and a Claude `Skill` call followed by an error result. This would inflate a skill-routing comparison.

## Decisions

- D1: Grade observable evidence and preserve the offline and live eval boundary -- why: the existing evaluation contract grades actual tool activity, and live model calls run only on request -- by: observed -- paths: evals/run.py tests/test_evals.py
- D2: Keep PASS and FAIL with an explicit reason when evidence is unverified -- why: the user approved all four recommended roadmap options -- by: user

## Scope

- Codex: require successful execution with the exact selected skill path and an observable prefix of the referenced skill content. An exact path mention alone is insufficient. Mark candidate evidence lacking content, such as truncated output, as unverified. No shell execution or general shell parser is needed in the evaluator.
- Claude: match each relevant `Skill` call to a tool result by ID. An error result is not a successful load. A missing result is unverified. Confirm the precise CLI JSONL envelope using sanitized fixtures before locking the matcher.
- Recommended report keeps `PASS|FAIL` and the current JSON pass field. Unverified evidence in a routing case is a failing result with an explicit reason, including a case expecting no load. Answer-only cases remain graded on their existing contract.
- Scope is `evals/run.py`, `tests/test_evals.py`, and the eval section of `README.md`. Use stubs and synthetic JSONL. Live evals, global skill changes, and rewriting case prompts are outside this proposal.

Codex documents separate item and turn events. Its current exec event implementation includes command output and exit code. The Claude tool protocol defines the tool-result ID and the error flag. These sources constrain what the offline fixtures can claim. [Codex JSONL](https://learn.chatgpt.com/docs/non-interactive-mode#make-output-machine-readable) · [Codex exec events](https://github.com/openai/codex/blob/main/codex-rs/exec/src/exec_events.rs) · [Claude tool results](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls#handling-errors-with-is-error)

## Acceptance tests

1. Codex fixture with a successful direct read and corresponding skill prefix counts usage. A successful command printing just the path does not pass the same expected-skill case. Failed, unfinished and incomplete evidence cases are distinguishable.
2. Claude fixture with matching call and successful result counts usage once. A failed result does not count it. A missing result reports unverified.
3. Existing positive and negative routing fixtures, repeat behavior, and answer-only checks pass under `scripts/check`. No paid run is needed to satisfy this draft.
